## How the tool list is narrowed

The planner never sees all 500 actions. Retrieval (BM25 over a search card per action, no model call) picks about 18 per question; see [docs/PLAN.md](docs/PLAN.md), section "Retrieve".

- **The search cards were written by an LLM.** `server/src/retrieval/cards.json` holds a description, synonyms, record types and look-alike siblings for each catalog action. They were generated by the planner model (`npm run cards`), not written by hand. The generator never sees `eval/`, and `retrieve.test.ts` fails if a synonym copies an eval paraphrase.
- **Review status:** the cards of the 5 built modules (M01, M03, M06, M48, M49) were read against their handlers; one fix was needed (search cards listed optional filters as required inputs, which pulled in unrelated cards). The other 45 modules' cards are unreviewed, and regenerating cards overwrites hand edits.
- Retrieval quality is measured with `npm run eval:retrieval` (recall@k per question group, with a held-out split).
